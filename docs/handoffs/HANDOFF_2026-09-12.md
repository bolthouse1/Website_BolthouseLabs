## Hard-won lessons — read before touching anything

- **Verify the rendered page, not the source.** A layout bug hid every legal page's title and
  description for two and a half weeks, and nobody noticed, because the front-matter looked right.
  After any change, fetch the built or live HTML and check `<title>` and the meta tags.
- **Proof-of-flip: never `grep mbp-trial-form`.** It returns 3 hits on a *gated* page and 4 on a
  flipped one: the scoped CSS and the inline script ship the id regardless of the flag. Use these:

  ```bash
  curl -sS https://mybodyprism.com/pricing | grep -c "Download free"        # 0 gated, 1 flipped
  curl -sS https://mybodyprism.com/pricing | grep -o '<form[^>]*id="[^"]*"' # rendered form id
  ```

  Also: `"Join the waitlist"` goes 4 → 0, and the five waitlist-promise strings go 5 → 0.
- **`/pricing/` still returns HTTP 404** even though people land correctly — the hop happens in the
  browser. Any uptime monitor or link checker that reads status codes will see a 404 on
  slash-ended URLs. That is expected. If `build.format` ever changes, re-check the redirect.
- **Legal mirrors:** re-sync with `git -C C:\Projects_MedViz\SomaViz_Desktop_Volume_Viewer show
  <commit>:legal/<file>.md` on **`release/v1.1`** — never from the desktop working tree (it was on
  `theme/prism-glass`, with stale legal text) and never from `main` (its `privacy-policy.md` differs).
  Port the **body** only. Front-matter is website-owned, and since `ba23072` it renders. Check each
  mirror content-identical to canonical after the port. **Check for canonical drift at the start of
  every session** — it moved again the same day as the last sync:

  ```bash
  git -C C:/Projects_MedViz/SomaViz_Desktop_Volume_Viewer fetch -q origin
  git -C C:/Projects_MedViz/SomaViz_Desktop_Volume_Viewer log --oneline 6bdaf2ef..origin/release/v1.1 -- legal/
  ```

  Once item 1 is done, empty output means the mirrors are current. Before then, the live mirrors
  still match `69c190cc`.
- **FDA wording and owner-directed copy are not a session's to reword.** That covers the footer
  disclaimer, the "diagnose or monitor?" FAQ, homepage sections 6–8, the `/pricing` lede, "How it
  works" step 1 and the free-beta FAQ. If one reads wrong, add alongside it and ask.
- **The Bash tool mis-parses large scripts with several heredocs** — it happened twice in this
  project. Both times nothing ran, but **verify the actual state after any parse failure** before
  retrying. Put Python/JS in files with the Write tool and run them; pass commit messages as `-m`
  arguments or `-F <file>`. A `\\` in a command gets halved.
- **Guarded pipelines:** make every pre-commit check a hard gate, and stage explicit paths —
  never `git add -A` while docs are dirty. After the deploy, compare the live pages with the build
  you verified.
- **No test suite.** `npm run build` is the only automated check. Build in **both** flag states
  whenever you touch anything gated.
