# Engineering handbook

How to work on this repository safely. It is deliberately the shortest handbook
in the portfolio, because the project has no toolchain to describe.

## Development procedure

### Setup

Nothing to install. Clone the repository and open
[`../index.html`](../index.html) in a browser. There is no package manifest, no
lockfile, no virtual environment, and no task runner. A local static server is
optional; opening the file from disk exercises everything except cross-origin
behavior.

The one script in the repository, [`create_asset_guide.py`](create_asset_guide.py),
is a one-off generator for the Word asset guide beside it. It needs `python-docx`
and is not part of the site build.

### Implementation

- All markup, styles, and behavior live in `index.html`. Keep it that way unless
  a decision record says otherwise.
- Styles go in the single `<style>` block. Colors come from the `:root` custom
  properties; do not hard-code a hex value that duplicates one of them.
- Behavior goes in an IIFE at the bottom of the document. No globals, no
  external scripts, no build step.
- Reveal-on-scroll is opt-in per element: add `.reveal`, plus
  `.reveal-delay-1|2|3` for stagger.
- Any new animation must be disabled or made static under
  `prefers-reduced-motion: reduce`, matching what the particle field and the
  reveals already do.
- New imagery goes at the repository root, referenced by bare filename, on a
  dark or black background. Motion uses
  `<video autoplay muted loop playsinline>`.

### Copy changes are governed

Before editing visible text, read the Brand Identity, Product Model, and Design
Rules sections of [`../CLAUDE.md`](../CLAUDE.md). Constraints that have bitten
before: never name the cloud provider, never mention who pays streaming costs,
never describe the product as concierge or mail-in, and keep "Bolthouse Labs"
out of everything except the footer copyright.

### Testing

There is no automated test and none is planned. Verification is a manual browser
pass:

1. Load the page. No console errors.
2. Hero: particle field animates; the logo and headline are centered; the scroll
   cue is visible.
3. Scroll the full page. Every section reveals; nothing jumps or reflows.
4. Narrow to ~375px. Sections tighten, trust badges stack, images stay inside
   the viewport, and nothing scrolls horizontally.
5. Fonts: headings render in Playfair Display, body in Outfit.
6. Submit a test address in the waitlist form. The form is replaced by the
   success line; the submission appears in the form provider's dashboard.
7. Enable reduced motion in the OS and reload. No particles; all content is
   visible without scrolling animation.

### Review and documentation

Small copy and asset changes go straight to `master`. Anything that changes the
page's structure, adds an external dependency, or changes what the product
claims should be recorded first as a decision record in
[`decisions/`](decisions), then implemented.

When the page structure changes, update
[`architecture/ARCHITECTURE.md`](architecture/ARCHITECTURE.md) and
[`../PROJECT_STATE.md`](../PROJECT_STATE.md) in the same commit. Documentation
lagging the markup is this repository's recorded historical failure mode.

### Handoff

A session ends cleanly when: `git status` is clean, the change is pushed to
`master`, the live domain shows it, and `../PROJECT_STATE.md` names the next
action.

## Safety and quality

### Deployment reality

Push to `master` is deployment. GitHub Pages rebuilds and publishes in one to
two minutes with no approval gate and no staging environment. Do not push
work-in-progress. Rollback is `git revert` plus a push.

The [`../CNAME`](../CNAME) file pins the custom domain. Deleting or editing it
changes what host GitHub Pages will serve — treat it as configuration, not
content.

### Things to leave alone

- `CNAME` — see above.
- The Formspree endpoint in the form's `action` — changing it silently redirects
  every future submission.
- The six `Picture*.png` filenames — replace contents, keep names, and the
  markup needs no edit.
- [`../STATUS.md`](../STATUS.md) — generated by portfolio tooling outside this
  repository; edits here can be overwritten.
- `.claude/` and `.superpowers/` — local-only, gitignored, never published.

### Privacy and secrets

The tracked tree contains no credentials. The public form endpoint is
necessarily visible in client HTML and is not a secret. The page sets no
cookies, loads no analytics, and sends nothing but a submitted email address to
one third party. Any change that adds a network call changes the trust story the
page tells in its own trust strip — treat it as a decision, not a detail.

### Documentation authorship boundary

This handbook and its sibling documents describe the repository; they do not
review it. Findings about code quality, defects, or remediation are out of
scope here. If a change is needed, it belongs in a decision record or the
roadmap, not in a documentation aside.
