# Agent guidance

## Project identity

`mybodyprism-com` is the public website for **MyBodyPrism**, a Bolthouse Labs,
Inc. product. It is an **Astro 6 static site** — pages in [`src/pages/`](src/pages),
one shared layout in [`src/layouts/Default.astro`](src/layouts/Default.astro) —
built with `npm ci && npm run build` and published to GitHub Pages at the domain
pinned in [`public/CNAME`](public/CNAME).

> It was a single-file `index.html` teaser until 2026-08-26, when owner decision
> moved v1.1 launch-site ownership here and the Astro site was migrated in from
> `AWS-HIPPA/web/`. Documents describing "one file, no build step" predate that.

Governing instruction file: [`CLAUDE.md`](CLAUDE.md). It applies to the whole
repository and outranks these notes on brand, copy, and product-claim questions.

## Operating rules

**Copy and brand are constrained.** Before writing or editing any visible text,
read the Brand Identity, Product Model, and Design Rules sections of
[`CLAUDE.md`](CLAUDE.md). The non-negotiables recorded there:

- **v1.1 ships the desktop app ONLY.** All imaging stays on the user's machine —
  no uploads, no cloud, no AI processing.
- **Do not claim streaming, browser viewing, VR, HIPAA-compliant cloud, or
  end-to-end encryption.** Those are roadmap (v1.2+), not shipped. Overselling
  copy was removed 2026-08-26 at the owner's direction; do not reintroduce it.
- If streaming copy ever returns: never name the cloud provider, and never
  mention who pays streaming costs.
- "Bolthouse Labs" appears only in the footer copyright line.
- All media must sit on dark or black backgrounds.

**Some copy is owner-directed and must not be reworded.** The `/pricing` lede,
the homepage "How it works" steps, and the support "Is it really free?" answer
are legally-adjacent and were dictated. If they read wrong in a given state, add
a separate notice alongside them — as the gated pre-launch notices do — rather
than editing the sentence.

**`src/pages/legal/*.md` are mirrors, not source.** Canonical text lives in the
desktop repo at `SomaViz_Desktop_Volume_Viewer/legal/`. Fix upstream first, then
re-sync here. Four of the eight have no upstream and originate here.

**The palette is defined once**, as `--c-*` tokens in the layout. Never hardcode a
colour in a page. Page `<style>` blocks are Astro-scoped, so a selector aimed at
something outside the component needs `:global(...)` or it silently never matches.

**Structure is easy to get wrong.** The site has been restructured more than once
and prose has trailed the markup every time. Read the actual file in `src/pages/`
before making any structural statement.

**Deployment is gated, in two independent ways.** Read the Deployment Notes and
"The launch switch" sections of [`CLAUDE.md`](CLAUDE.md) before touching either:

- Publishing requires the Pages source set to "GitHub Actions". Merging to
  `master` while it is still "deploy from branch" takes the live domain down.
- `PUBLIC_DOWNLOADS_LIVE` gates the download flow. Do not flip it before tracker
  step W4.1 — an early flip silently drops signups.

**Treat these as read-only unless the task is explicitly about them:**
[`public/CNAME`](public/CNAME) (if it stops reaching `dist/`, the custom domain
unbinds and the site goes dark), the six `Picture*.png` files and their
filenames, and [`STATUS.md`](STATUS.md) (regenerated by portfolio tooling outside
this repository).

**Verification is manual.** There is no test suite. `npm run build` is the only
automated check and it catches syntax, not sense. Build in **both** flag states
(`PUBLIC_DOWNLOADS_LIVE` unset, then `=true`) when touching anything gated, then
open `dist/` and confirm: the reveal animations fire, the layout holds at ~375px,
the fonts load, and `dist/CNAME` is present. Respect `prefers-reduced-motion`
when touching animation code — and keep the `.js-reveal` gate, without which the
page renders blank with JS disabled.
